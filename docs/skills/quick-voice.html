quick-voice v1.0

Instant browser voice session (OpenAI Realtime gpt-realtime-2) — close a topic in a short conversation instead of working through documents.

What it does

White-label voice-session generator. Each invocation spins up a per-session web app that opens a WebRTC channel to the OpenAI Realtime API with context-specific instructions, tools, and a generic canvas. Talk for 3 minutes instead of working for 30.

Two modes

ModeToolsOutput
liveFile / JSON / bash tools — agent reads & updates real data during the callSummary of changes in output.md
distillNo data-mutation tools — only canvas + notesLong structured deliverable (decisions, action items)

Generic canvas (both modes)

The agent can call canvas_show({ type, source, content, title }) to display content live in the browser, then react to user feedback by voice. Supported types: image, markdown, html, code, json, video, audio, url (iframe), text. Local files are served through a sandboxed /file endpoint scoped to the session's working directory.

Prerequisites

  • Node.js 18+ (uses native fetch)
  • OpenAI API key with Realtime API access
  • A modern browser (Chrome / Edge recommended for WebRTC)

Setup

  1. Install: clone or copy the skill into ~/.claude/skills/quick-voice/
  2. Add your key: 
    cp ~/.claude/skills/quick-voice/.env.example ~/.claude/skills/quick-voice/.env
# Edit and set OPENAI_API_KEY=sk-...
  3. The launcher auto-runs npm install on first launch (express + dotenv).

How a session runs

  1. You tell Claude: "Let's close X in a voice call" (or it infers from context).
  2. Claude generates runtime/<id>/config.json with mode, instructions, tool whitelist, canvas hints, and output template.
  3. Claude runs node ~/.claude/skills/quick-voice/scripts/launch.js <id>:
    • Finds a free port in 3031–3040 via net.createServer
    • Spawns server.js
    • Opens the default browser at http://localhost:<port>
    • Waits until the session ends (close browser, click ✓, or the agent calls end_session)
  4. Launcher prints output.md back to Claude for follow-up.

Available tools (whitelist via config.json.tools)

Canvas + control (both modes)

  • canvas_show({ type, source, content, title?, language? })
  • canvas_clear()
  • save_note({ heading, content }) — appends to output.md
  • end_session({ summary? }) — finalize + close

Data (live mode)

  • read_file, write_file, append_file
  • update_json — shallow-merge into a JSON object root
  • array_update_json — surgical update of one record in a JSON array (by match field)
  • list_dir, run_bash

Example configs

"Let's go over the images I just generated" (distill)

{
  "mode": "distill",
  "topic": "Image review",
  "instructions": "Walk through each image. canvas_show → ask 'thoughts?' → listen → save_note('Image N — feedback', user_reply). Call end_session when all done.",
  "voice": "ash",
  "tools": ["canvas_show", "canvas_clear", "save_note", "end_session"],
  "canvas_hints": [
    { "type": "image", "source": "/abs/path/img-001.png", "title": "1" },
    { "type": "image", "source": "/abs/path/img-002.png", "title": "2" }
  ],
  "output_template": "# Image feedback\n\n"
}

"Review pending freelancer scores" (live)

{
  "mode": "live",
  "topic": "Freelancer review",
  "instructions": "read_file freelancers.json. For each freelancer, canvas_show type=json, ask for new score, update via array_update_json. Log via save_note. end_session.",
  "voice": "ash",
  "cwd": "/Users/aviz/aviz-crm",
  "tools": ["canvas_show", "save_note", "end_session", "read_file", "array_update_json"],
  "output_template": "# Freelancer review\n\n## Updates\n\n"
}

Architecture

quick-voice/
├── SKILL.md
├── package.json
├── server.js              # Express, /token /config /tool/:name /file /done
├── public/
│   ├── index.html
│   ├── styles.css
│   └── app.js             # WebRTC + canvas renderer + tool dispatch
├── lib/
│   ├── tool-defs.js       # OpenAI Realtime tool schemas
│   └── tools.js           # Server-side tool implementations
├── scripts/
│   └── launch.js          # Cross-platform launcher (macOS/Linux/Windows)
└── runtime/<id>/         # Per-session: config.json, output.md, server.log, done.flag

Anti-patterns

  • Don't bake the OpenAI key into config or HTML — keep it in .env
  • Keep instructions ≤ 2KB. Realtime agents act on short, specific prompts.
  • Always set cwd when enabling file tools — it scopes the blast radius.
  • Enable run_bash only when truly needed. Prefer specific tools.
  • Don't auto-delete runtime/<id>/ — the user may want to re-open or audit.

Troubleshooting

  • "Server did not become ready in 8s" — check runtime/<id>/server.log; usually a bad OPENAI_API_KEY or missing dep.
  • Browser doesn't open — the launcher prints the URL. Open manually.
  • SDP error from OpenAI — verify your account has Realtime API access.
  • Tool errors in transcript — open the browser devtools console and check the server.log for the matching error.
