Hermes Tweet

Hermes Agent X/Twitter automation through Xquik, with read-first workflows and explicit action gating.

Native Hermes Agent plugin

Hermes Tweet installs through the Hermes plugin manager and exposes tweet_explore, tweet_read, and tweet_action as a dedicated Hermes toolset.

Xquik is an independent third-party service. Not affiliated with X Corp. "Twitter" and "X" are trademarks of X Corp.

What It Does

  • Discovers cataloged Xquik endpoints with tweet_explore.
  • Runs read-only X/Twitter workflows with tweet_read.
  • Keeps posting, replies, likes, follows, DMs, monitors, webhooks, draws, and media changes behind tweet_action.
  • Supports Hermes Desktop, CLI, TUI, cron, and remote gateway profiles where the runtime is configured.

Install

Install and enable the plugin with Hermes:

hermes plugins install Xquik-dev/hermes-tweet --enable

If it is already installed but disabled:

hermes plugins enable hermes-tweet

Configure

Set the API key on the machine that runs the Hermes plugin code:

export XQUIK_API_KEY="xq_your_key"

For non-interactive gateway or cron profiles, put the key in the Hermes runtime environment or ~/.hermes/.env, then restart or reload that runtime.

Action tools stay disabled by default

Only enable account-changing routes in sessions that explicitly need them:

export HERMES_TWEET_ENABLE_ACTIONS=true

Tooling Model

ToolPurpose
tweet_exploreSearch the bundled endpoint catalog without an API call.
tweet_readCall catalog-listed read-only endpoints after XQUIK_API_KEY is set.
tweet_actionCall write-like or private endpoints only when actions are enabled.

Usage Pattern

  1. Use tweet_explore to find a matching endpoint.
  2. Use tweet_read for public or account read routes.
  3. Use tweet_action only after naming the endpoint, payload, and account-changing effect.
  4. Never paste API keys, session data, or credentials into tool arguments.
